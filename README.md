# CellLock 0.4.8（本地验证，未发布）

已 Root 高通手机上的免费网络设置工具。原有写入验证设备为小米 14 Pro（23116PN5BC / SM8650 / Android 14）；0.4 自适应读取已在 SM8250 / Android 13 / MIUI 14 的正式 App 验证，详见 [开发交接文档](docs/DEVELOPMENT.zh-CN.md)。无会员、广告或联网 SDK，应用未声明 `INTERNET` 权限。

## 功能

- **小区**：保留普通接口、Root 电话、QMI NAS 与 NR 诊断观测；按所选 SIM 补读射频频段、系统信息、独立信号和 NAS 邻区。核对服务身份后补缺，NR 频段与频点冲突时校正；正常系统频段保留，重叠候选无法确认时留待手选。有效频段统一用于显示、邻区匹配和锁定填表，不因校正取消合格邻区的资格。前台读取结束约 5 秒后重试；诊断邻区合并最近 15 秒，切卡或服务载波变化时清空。有效系统测量绘制最近 5 分钟、最多 60 点的曲线；QMI 补入的信号不冒充原始测量点。
- **锁定**：LTE 小区锁、5G NR 小区或频点锁；选择 LTE、NR、GSM、WCDMA 频段；设置网络制式与 5G SA / NSA 组网。
- **设备**：查看机型、硬件支持频段、Root / 后端状态、读取权限和操作记录，按需导出诊断。

0.4.4 精简页面副标题、SIM 来源、当前连接详情和实现说明，保留邻区信号质量；修复信号强弱文字截断。锁定页按“制式 / 频段 / 小区”和“5G NR / LTE”排列，按钮简化为“锁定 / 清除解锁”，状态读取失败继续显示“未知”。NAS 补读仅添加新的观测，已有电话服务数据优先，未确认映射的 NR 不替换可信 LTE 服务；这不保证基带返回其他 NR 频段，调查见 [开发交接中的读取覆盖说明](docs/DEVELOPMENT.zh-CN.md)。

0.4.3 修正空结果引导触发连续刷新的问题，电话 / 位置授权分别记录申请历史；同频 NR 邻区的推算频段优先匹配已知服务频段，显示与填表一致。DIAG 连续两轮无包后重新尝试另一入口，手动刷新重新探测。NAS 保留可用的 PLMN、TAC、CI/NCI，邻区不继承服务小区标识；ICCID 继续脱敏，测试归档另行脱敏网络标识。原生构建统一由 `native/build.ps1` 执行，原有两种入口保持可用。

0.4.2 放宽同频邻区的填表资格：与当前服务制式、频段、频点一致，PCI 有效且刚接收的 NAS / DIAG 观测可用作锁定目标，不冒充已确认的 SIM 归属。诊断邻区跨轮合并最近 15 秒，逐小区过期，选卡或观察到服务频段 / 频点变化时清空。普通、Root 电话和底层观测逐字段保留有效信号、质量与身份信息，PCI 占位值不再导致整条记录丢失；未知协议和非法身份仍拒绝。

0.4.1 修复禁用 Root 后普通接口有信号却不显示的回归：PCI 不可用时继续显示有效信号与其他字段，仅禁止将身份不完整的记录填入目标；Root 可用时继续尝试补全。NR 诊断改为合并同一短会话内的多包观测，不再只读取最后一包，减少邻区遗漏；这不代表已达到 Cellular-Pro 的完整覆盖。

0.4.0 接入按已有权限与设备能力自动选路的读取流程：普通电话接口受“空白授权”等限制时，自动尝试 Root 电话、QMI UIM / NAS 和 NR DIAG。Root 可直接读取的 SIM / 小区信息不再受统一电话、定位权限门槛限制，不新增 Root 开关，也不自动修改授权或系统定位。修复 DIAG 执行路径兼容性，首次加入诊断观测缓存，手动刷新可在 Root 授权恢复后补读真实订阅并保留所选卡；后台停止采集并清理短会话。

0.3.0 已从 App 验证 SIM 1 的 LTE B3 频段设置、SIM 2 的 NR SA + NSA n1 / n78 设置；直接调用同一后端也验证了双卡制式与 SIM 2 组网切换，随后完整恢复原值。SIM 2 的 LTE 小区锁配置及解除均已回读确认，实际 LTE 目标驻留未验证。**NR 小区锁和 ARFCN 频点锁的实际效果尚未完成实机验证**；即使已观测到真实 NR 服务，成功空应答仍按锁定状态未知处理。最终两卡配置与测试前一致，移动数据及漫游保持关闭。具体回执见 [验证记录](native/VALIDATION.md)。

## 使用

1. 安装 APK，在 Root 管理器中允许 CellLock。应用根据实际读取结果自动选路，不修改系统权限或定位开关。
   普通电话接口可能受 MIUI“空白授权”限制；支持的 Root 路径会自动补充 SIM 和小区信息，无需新增开关。只有普通系统小区接口需要精确位置及系统定位；Root 能直接读取的信息不受这一统一门槛限制。手动“刷新”仍无法读取时才引导必要授权。无 Root 时仍可读取公开卡状态，具体小区能力取决于系统权限与接口。
2. 选择上方 SIM，首次进入“锁定”或“设备”页自动读取当前配置；软件按每张卡保存首次完整读取的初始频段与制式，已有快照不会覆盖。
3. 从“小区”页选择目标，或在“锁定”页选择“制式 / 频段 / 小区”，核对参数后确认写入。NR 频段与 SCS 建议值可以手改。
4. 查看回读结果。配置确认后，可返回“小区”页观察实际驻留；两者不是同一项验证。

目标错误或仅选择无覆盖的网络可能暂时断网；离开目标覆盖区前记得恢复。应用不会打开移动数据或数据漫游。

## 两种恢复

- **恢复初始配置**：恢复该 SIM 首次保存的完整频段、制式、NR 组网及原始 legacy 掩码，并分别请求解除 LTE / NR 小区锁。恢复按完整原值比对，保留初始配置中硬件不支持的频段位。
- **开放全部支持范围**：开放本机硬件支持的频段与制式，启用 SA + NSA，并请求解除小区锁。它会改变原有频段限制，不能代替“恢复初始配置”。

锁定页的“解除 5G 小区锁 / 解除 LTE 小区锁”只解除所选制式的小区、频点锁，不恢复频段或制式。已明确无锁时不重复写入；基带拒绝、状态未知与真实不一致分别展示。配置恢复成功但清锁失败时仍显示部分结果，不能据此认定已解除。两种恢复均不删除其他工具的 EFS 文件。两张 SIM 分别保存初始配置，操作前核对所选卡。

## 构建与测试

需要 JDK 17、Android SDK 35、Android NDK。Gradle Wrapper 已随源码提供。在项目根目录的 `local.properties` 配置 `sdk.dir`，然后运行：

```powershell
./build-native.ps1 -Ndk 'C:/你的/android-sdk/ndk/30.0.14904198' -BuildTests
./gradlew.bat clean assembleDebug lintDebug
```

纯测试还包括 `tests/MeasurementDecoderTest.java`，覆盖 NR 版本/长度、QMI 绑定/字段和观测安全边界。`tests/run-host.ps1` 可在 PC 运行参数、历史、SIM、快照和解析测试，需要 SDK `android.jar` 作为类型定义，以及独立 `org.json` 测试运行库；测试库和时钟替身不打入 APK。完整命令见 [交接文档](docs/DEVELOPMENT.zh-CN.md)。全部纯测试只检查逻辑，不发送基带命令。既有真机结果见 [验证记录](native/VALIDATION.md)。
